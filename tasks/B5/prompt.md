在当前目录从零搭一个「记账数据导入和统计」后端服务。技术栈固定：Cloudflare Workers（TypeScript）+ D1 数据库，用 wrangler 本地开发。目录里已经装好了 wrangler（见 package.json），需要别的依赖可以自己加。

## 背景

一个记账 App：用户从银行或别的记账软件导出 CSV 文件，上传到这里，每一行是一笔带时间的支出；服务校验后存进数据库，再按天、按周、按月给出笔数和金额合计。用户分布在不同时区，「哪一天」一律按用户自己设置的时区算。导入接口比较重，每个用户每分钟只能调几次。

## 通用约定（验收测试按这个调用）

- 除了导入接口的请求体是 CSV，其余接口都收发 JSON。出错时返回对应状态码，响应体 `{"error": "说明"}`（说明随意）。
- 除了注册和登录，所有接口都要请求头 `Authorization: Bearer <token>`；缺少、无效返回 401。
- JSON 请求体不合法、缺必填字段、字段类型或取值不对，返回 400；查询参数不合法也返回 400。
- id 一律是字符串，格式自定。
- 令牌可以是存库的随机串，也可以是签名令牌；用到的签名密钥从环境变量 `TOKEN_SECRET` 读。密码不许明文存库。
- 日期一律写成 `YYYY-MM-DD`，必须是真实存在的日期（`2026-02-30` 不合法）。

## 接口约定

### 1. 账号和时区

- `POST /v1/auth/register`，请求 `{"email": "a@example.com", "password": "至少 8 位"}`。邮箱要含 `@`，密码至少 8 个字符，否则 400。邮箱不区分大小写，已被注册返回 409。成功返回 201：`{"user": {"id": "...", "email": "a@example.com"}, "token": "..."}`（email 一律存成小写）。
- `POST /v1/auth/login`，请求同上。成功返回 200，响应同注册；邮箱或密码不对返回 401。
- `GET /v1/me` 返回 200：`{"id": "...", "email": "...", "timezone": "UTC"}`。新用户的时区是 `UTC`。
- `PATCH /v1/me`，请求 `{"timezone": "Asia/Singapore"}`，时区必须是 IANA 时区名（如 `Asia/Singapore`、`America/New_York`、`Asia/Kolkata`、`UTC`），不认识的返回 400。只能改时区，请求里别的字段忽略。返回 200 和更新后的 `/v1/me` 内容。
- 改了时区之后，所有统计和按日期的筛选都立刻按新时区算，包括以前导入的记录。

### 2. 导入

`POST /v1/imports`，请求头 `Content-Type: text/csv`（可以带 `; charset=utf-8` 这类参数），请求体就是 CSV 文件的内容。

CSV 格式：

- 第一行是表头，必须是 `time,amount,category,note` 这四列、这个顺序（每个列名去掉首尾空白后比较）。表头不对，或者文件是空的，整个文件拒绝，返回 400，一条都不导入。
- 文件开头可能带 UTF-8 BOM，要忽略。换行可能是 `\n` 也可能是 `\r\n`。
- 从第二行起每行一笔记录。完全空的行（包括文件末尾的换行）直接跳过，不算坏行。
- 字段用逗号分隔；字段可以用双引号括起来，括起来的字段里可以有逗号，`""` 表示一个双引号（比如 `"他说""好吃"""` 就是 `他说"好吃"`）。字段里不会有换行。每个字段去掉首尾空白后再校验。
- 每行必须正好 4 个字段（`note` 可以是空的，但逗号不能少）：
  - `time`：格式固定为 `YYYY-MM-DDTHH:MM:SS` 后面跟 `Z` 或 `±HH:MM` 时差，比如 `2026-03-01T09:30:00+08:00`、`2026-03-01T01:30:00Z`。日期时间必须真实存在（月 1–12、日不超过当月天数、时 0–23、分秒 0–59）。
  - `amount`：大于 0、不超过 1000000 的金额，最多两位小数，比如 `12`、`12.5`、`12.50`；负数、`0`、三位小数、非数字都不合法。存成整数「分」，换算不能有误差（`1.15` 必须是 115 分）。
  - `category`：1–30 个字符。
  - `note`：0–200 个字符。

处理规则：

- 不合法的行跳过、不导入，其余合法的行照常导入。行号按文件里的物理行数算，表头是第 1 行，空行也占行号。
- 一次导入要么全部合法行都存进去，要么一行都不存（不能存一半）。
- 请求体超过 1 MB（1048576 字节）直接拒绝，返回 413，一条都不导入。
- `Content-Type` 不是 `text/csv` 返回 415。
- 成功返回 201：

```json
{ "import_id": "...", "imported": 7, "rejected": [{"line": 3, "reason": "说明随意"}, {"line": 9, "reason": "..."}] }
```

`rejected` 按行号从小到大，没有坏行就是空数组。

`DELETE /v1/imports/{import_id}` 删除这次导入和它导入的所有记录，返回 204。不存在或不是我的导入返回 404。

### 3. 导入次数限制

- 每个用户在任意连续 60 秒内最多调用导入接口 5 次。所有带有效令牌的调用都算次数，包括返回 400、413、415 的；第 6 次起返回 429，不处理内容、一条都不导入；被 429 拒掉的那次不算次数。
- 先判断次数，再看请求体：超出次数的调用不管内容是什么都返回 429。
- 次数按用户分开算，一个用户用完了不影响别人。只限导入接口，别的接口不受影响。

### 4. 记录列表

`GET /v1/records` 返回我的记录，200：

```json
{ "records": [{"id": "...", "time": "2026-03-01T01:30:00Z", "amount_cents": 1250, "category": "餐饮", "note": "", "import_id": "..."}], "next_cursor": "..." }
```

- `time` 一律换算成 UTC，格式 `YYYY-MM-DDTHH:MM:SSZ`。
- 按时间从早到晚排；时间完全相同的按记录 `id` 的字符串顺序从小到大。
- 可选查询参数 `from`、`to`：按我的时区算的本地日期，含两端；只给一个也行；两个都给时 `from` 不能晚于 `to`，否则 400。
- `limit`：每页条数，1–100，默认 20；超出范围或不是整数返回 400。`cursor`：上一页返回的 `next_cursor`，原样带回（`from`、`to` 也照原样带上）；无法识别返回 400。没有下一页时 `next_cursor` 为 null。
- 翻页必须不重不漏：从第一页一直翻到最后一页，每条记录正好出现一次；翻页途中删掉一次导入（不管它的记录是否已经返回过），剩下的记录照样每条正好出现一次。

### 5. 统计

`GET /v1/stats?period=day&from=2026-03-01&to=2026-03-31`

- `period` 是 `day`、`week`、`month` 之一；`from`、`to` 必填，都是按我的时区算的本地日期，含两端；`from` 不能晚于 `to`，从 `from` 到 `to` 最多 366 天（含两端）。不合法返回 400。
- 只统计本地日期在 `from` 到 `to` 之间的记录，按 `period` 分组：
  - `day`：按本地日期分组；
  - `week`：一周从**周一**开始，到周日结束；
  - `month`：按本地的自然月。
- 每组的 `start` 是这一组第一天的本地日期：`day` 就是那一天，`week` 是那周的周一，`month` 是那个月的 1 号（即使 `from` 在组的中间，`start` 也照这个规则写，组里只算 `from`、`to` 范围内的记录）。
- 只返回有记录的组，按 `start` 从早到晚排。返回 200：

```json
{ "period": "week", "timezone": "Asia/Singapore", "from": "2026-03-01", "to": "2026-03-31",
  "buckets": [{"start": "2026-02-23", "count": 1, "total_cents": 1250}, {"start": "2026-03-02", "count": 3, "total_cents": 4550}] }
```

- 本地日期按时区的真实规则算，包括夏令时：比如 `America/New_York` 冬天比 UTC 慢 5 小时、夏天慢 4 小时；`Asia/Kolkata` 比 UTC 快 5 小时 30 分；`Asia/Singapore` 比 UTC 快 8 小时，`2026-03-01T16:00:00Z` 在新加坡已经是 3 月 2 日。

## 交付要求

- wrangler 配置文件里 D1 的绑定名叫 `DB`；数据库迁移放在 `migrations/` 目录，用 `npx wrangler d1 migrations apply DB --local` 能建好表。
- 本地用 `npx wrangler dev --local` 能启动。密钥从环境变量读（本地放在 `.dev.vars`），不要写死在代码里。
- 接近 1 MB 的文件（两万行左右）也要能完整导入。
- 多个请求可能同时到达（比如同一个用户同时发好几个导入请求，同一个邮箱同时注册），结果必须和一个一个来时一样正确：同一个用户同时发 8 个导入，只能有 5 个成功。
- 自己写测试验证上面的规则。
- 不要部署，不要登录 Cloudflare 账号。
