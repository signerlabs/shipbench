在当前目录从零搭一个「附近的店和评分」后端服务。技术栈固定：Cloudflare Workers（TypeScript）+ D1 数据库，用 wrangler 本地开发。目录里已经装好了 wrangler（见 package.json），需要别的依赖可以自己加。

## 背景

一个找店 App：用户在地图上看自己附近有哪些店，按距离从近到远一页一页往下翻；看中的店可以收藏，吃过可以打分。店铺数据也由用户自己添加。用户遍布全球，包括高纬度地区和国际日期变更线（经度 180°）两边的岛国。

## 通用约定（验收测试按这个调用）

- 所有接口收发 JSON。出错时返回对应状态码，响应体 `{"error": "说明"}`（说明随意）。
- 除了注册和登录，所有接口都要请求头 `Authorization: Bearer <token>`；缺少、无效返回 401。
- 请求体不是合法 JSON、缺必填字段、字段类型或取值不对，返回 400。请求体超过 64 KB 返回 413。查询参数不合法也返回 400。
- id 一律是字符串，格式自定。
- 令牌可以是存库的随机串，也可以是签名令牌；用到的签名密钥从环境变量 `TOKEN_SECRET` 读。密码不许明文存库。
- 访问不存在的店（包括已经删掉的）返回 404。店不存在时一律先返回 404，不管有没有权限、请求体对不对。

### 距离怎么算

- 一律按球面大圆距离（haversine 公式）算，地球半径取 **6371000 米**。经纬度都是度数，先换成弧度：

```
a = sin²(Δ纬度 / 2) + cos(纬度1) · cos(纬度2) · sin²(Δ经度 / 2)
距离 = 2 · 6371000 · asin(√a)
```

- 接口返回的 `distance_m` 是四舍五入到整数的米数；排序和半径判断用没取整的精确距离。
- 距离必须对全球任何位置都对：经度 179.999° 和 −179.999° 的两个点只相隔两百来米；纬度越高，经度一度代表的距离越短。

## 接口约定

### 1. 账号

- `POST /v1/auth/register`，请求 `{"email": "a@example.com", "password": "至少 8 位"}`。邮箱要含 `@`，密码至少 8 个字符，否则 400。邮箱不区分大小写，已被注册返回 409。成功返回 201：`{"user": {"id": "...", "email": "a@example.com"}, "token": "..."}`（email 一律存成小写）。
- `POST /v1/auth/login`，请求同上。成功返回 200，响应同注册；邮箱或密码不对返回 401。
- `GET /v1/me` 返回 200：`{"id": "...", "email": "..."}`。

### 2. 店铺

店铺结构：

```json
{
  "id": "...", "name": "阿婆牛杂", "lat": 22.2819, "lng": 114.1582, "created_by": "<user_id>",
  "rating_avg": 4.33, "rating_count": 3, "my_rating": 5, "favorited": true
}
```

- `rating_avg`：所有人打分的平均值，四舍五入保留 2 位小数；还没人打分时为 null。`rating_count`：打过分的人数。
- `my_rating`：我打的分，没打过为 null。`favorited`：我有没有收藏。这两项因看的人而不同。

接口：

- `POST /v1/shops`，请求 `{"name": "阿婆牛杂", "lat": 22.2819, "lng": 114.1582}`。`name` 去掉首尾空白后 1–100 个字符；`lat` 是 −90 到 90 的数字，`lng` 是 −180 到 180 的数字（都含两端），否则 400。任何登录用户都能加店，加的人记为 `created_by`。返回 201 和店铺。
- `GET /v1/shops/{shop_id}` 返回 200 和店铺。
- `PATCH /v1/shops/{shop_id}` 部分更新 `name`、`lat`、`lng`，只改请求里出现的字段，校验同新建。只有加这家店的人能改，别人返回 403。返回 200 和店铺。
- `DELETE /v1/shops/{shop_id}`，只有加这家店的人能删，别人返回 403；成功返回 204。删掉之后这家店不再出现在附近列表和任何人的收藏里，它的打分也一起作废。

### 3. 附近的店

`GET /v1/shops/nearby?lat=22.28&lng=114.16&radius_m=2000`

- 必填 `lat`、`lng`（范围同上）和 `radius_m`（1–50000 的整数），缺少或不合法返回 400。
- 返回距离不超过 `radius_m`（含等于）的店，按距离从近到远排；距离完全相同的按店铺 `id` 的字符串顺序从小到大。
- 返回 200：`{"shops": [店铺结构再加 "distance_m": 132, ...], "next_cursor": "..." 或 null}`，比如：

```json
{
  "shops": [
    {"id": "...", "name": "阿婆牛杂", "lat": 22.2819, "lng": 114.1582, "created_by": "...",
     "rating_avg": 4.33, "rating_count": 3, "my_rating": null, "favorited": false, "distance_m": 132},
    {"id": "...", "name": "陈记粥铺", "lat": 22.2841, "lng": 114.1575, "created_by": "...",
     "rating_avg": null, "rating_count": 0, "my_rating": null, "favorited": true, "distance_m": 377}
  ],
  "next_cursor": "..."
}
```

- `limit`：每页条数，1–50，默认 20；超出范围或不是整数返回 400。`cursor`：上一页返回的 `next_cursor`，原样带回（查询参数 `lat`、`lng`、`radius_m` 也照原样带上）；无法识别返回 400。没有下一页时 `next_cursor` 为 null。
- 翻页必须不重不漏：从第一页一直翻到最后一页，范围内的每家店正好出现一次；翻页途中删掉已经返回过的店（包括上一页的最后一家），后面的页照样接着往下，不重不漏。

### 4. 收藏

- `PUT /v1/shops/{shop_id}/favorite` 收藏，返回 204。已经收藏过再收藏也返回 204，不产生第二条。
- `DELETE /v1/shops/{shop_id}/favorite` 取消收藏，返回 204；本来就没收藏也返回 204。
- `GET /v1/me/favorites` 我的收藏，返回 200：`{"shops": [店铺, ...], "next_cursor": "..." 或 null}`，按收藏的先后排（重复收藏不改变先后）。分页参数 `limit`、`cursor` 规则同上，翻页同样必须不重不漏（翻页途中取消收藏已经返回过的店，后面照样接着往下）。
- 收藏只有自己看得到；收藏别人加的店完全可以。
- 店被删掉后，它从所有人的收藏里消失；收藏和取消收藏已删的店返回 404。

### 5. 打分

- `PUT /v1/shops/{shop_id}/rating`，请求 `{"score": 4}`，`score` 必须是 1–5 的整数，否则 400。每个人对每家店只有一个分：再打一次就覆盖之前的分，打分人数不变。返回 200：`{"rating_avg": 4.33, "rating_count": 3, "my_rating": 4}`。
- `DELETE /v1/shops/{shop_id}/rating` 撤回我的分，返回 204（本来没打过也返回 204）。撤回后打分人数减一，平均分重新算；所有人都撤回后平均分回到 null、人数为 0。
- 打分只影响自己的那一份：别人打分、改分、撤回，都不会动我的 `my_rating`。
- 平均分是「四舍五入」不是截断：三个人打 5、5、4，平均分是 4.67。
- 店铺结构里的 `rating_avg`、`rating_count`、`my_rating`、`favorited` 在单查、附近列表、我的收藏里都要有，而且一致。

## 交付要求

- wrangler 配置文件里 D1 的绑定名叫 `DB`；数据库迁移放在 `migrations/` 目录，用 `npx wrangler d1 migrations apply DB --local` 能建好表。
- 本地用 `npx wrangler dev --local` 能启动。密钥从环境变量读（本地放在 `.dev.vars`），不要写死在代码里。
- 多个请求可能同时到达（比如很多人同时给同一家店打分，同一个人同时连点好几次打分或收藏，同一个邮箱同时注册），结果必须和一个一个来时一样正确：平均分和打分人数一个都不能错。
- 自己写测试验证上面的规则。
- 不要部署，不要登录 Cloudflare 账号。
