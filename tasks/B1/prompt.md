在当前目录从零搭一个「多人共享清单」后端服务。技术栈固定：Cloudflare Workers（TypeScript）+ D1 数据库，用 wrangler 本地开发。目录里已经装好了 wrangler（见 package.json），需要别的依赖可以自己加。

## 背景

一个清单 App：用户建自己的清单（购物、旅行打包、搬家要办的事），清单里是一条条待办项，可以勾选、改文字、调整顺序。清单可以分享给其他用户，分「只读」和「可编辑」两种权限；也可以把任何自己看得到的清单「复制一份」当模板用，复制出来的是一份全新的、属于自己的清单。

## 通用约定（验收测试按这个调用）

- 所有接口收发 JSON。出错时返回对应状态码，响应体 `{"error": "说明"}`（说明随意）。
- 除了注册和登录，所有接口都要请求头 `Authorization: Bearer <token>`；缺少、无效返回 401。
- 请求体不是合法 JSON、缺必填字段、字段类型或取值不对，返回 400。请求体超过 64 KB 返回 413。
- id 一律是字符串，格式自定。
- 令牌可以是存库的随机串，也可以是签名令牌；用到的签名密钥从环境变量 `TOKEN_SECRET` 读。密码不许明文存库。

### 权限

每个清单对每个用户有一种身份：

| 身份 | 能做什么 |
|---|---|
| `owner`（建清单的人） | 全部：读、改标题、增删改待办项、调整顺序、分享和取消分享、删除清单 |
| `edit`（被分享为可编辑） | 读、改标题、增删改待办项、调整顺序；不能分享、不能删除清单 |
| `read`（被分享为只读） | 只能读 |
| 没被分享 | 看不到 |

- 看不到的清单（不存在、没被分享、分享已被取消、清单已删除），任何接口一律返回 404，不透露它是否存在。
- 看得到但没有这个操作的权限，返回 403（比如只读的人加待办项，可编辑的人删清单）。
- 取消分享、删除清单立刻生效：之后被取消的人再访问这个清单的任何接口都是 404。

## 接口约定

### 1. 账号

- `POST /v1/auth/register`，请求 `{"email": "a@example.com", "password": "至少 8 位"}`。邮箱要含 `@`，密码至少 8 个字符，否则 400。邮箱不区分大小写，已被注册返回 409。成功返回 201：`{"user": {"id": "...", "email": "a@example.com"}, "token": "..."}`（email 一律存成小写）。
- `POST /v1/auth/login`，请求同上。成功返回 200，响应同注册；邮箱或密码不对返回 401。
- `GET /v1/me` 返回 200：`{"id": "...", "email": "..."}`。

### 2. 清单

清单结构（下文称「清单摘要」）：

```json
{ "id": "...", "title": "周末采购", "owner_id": "...", "permission": "owner", "item_count": 3 }
```

`permission` 是我对这个清单的身份（`owner`、`edit`、`read`），`item_count` 是待办项条数。

- `POST /v1/lists`，请求 `{"title": "周末采购"}`。`title` 去掉首尾空白后 1–100 个字符，否则 400。返回 201 和清单摘要（`permission` 为 `owner`，`item_count` 为 0）。
- `GET /v1/lists` 列出我能看到的清单（我建的 + 分享给我的），返回 200：`{"lists": [清单摘要, ...], "next_cursor": "..." 或 null}`。
  - 按清单的创建先后排。
  - 查询参数 `limit`：每页条数，1–100，默认 20；超出范围或不是整数返回 400。`cursor`：上一页返回的 `next_cursor`，原样带回；无法识别返回 400。没有下一页时 `next_cursor` 为 null。
  - 翻页必须不重不漏：从第一页一直翻到最后一页，每个清单正好出现一次；翻页途中删掉已经返回过的清单（包括上一页的最后一个），后面的页照样接着往下，不重不漏。
- `GET /v1/lists/{list_id}` 返回 200：清单摘要再加 `"items": [待办项, ...]`，待办项按 `position` 从小到大。
- `PATCH /v1/lists/{list_id}`，请求 `{"title": "新标题"}`，owner 和 edit 可以改。返回 200 和清单摘要。
- `DELETE /v1/lists/{list_id}`，只有 owner 能删，返回 204。

### 3. 待办项

待办项结构：

```json
{ "id": "...", "text": "牛奶", "done": false, "position": 0 }
```

- 一个清单里待办项的 `position` 永远是从 0 开始的连续整数（0、1、2……），不重复、不跳号。新增、删除、移动之后都要保持这一点。
- `POST /v1/lists/{list_id}/items`，请求 `{"text": "牛奶"}`。`text` 去掉首尾空白后 1–500 个字符，否则 400。新项加在最后（`position` 等于原来的条数），`done` 为 false。返回 201 和待办项。
- `PATCH /v1/lists/{list_id}/items/{item_id}` 部分更新，只改请求里出现的字段：
  - `text`：规则同新建；
  - `done`：必须是布尔值；
  - `position`：把这一项移到这个位置（0 到 条数 − 1 的整数，否则 400），其余项依次顺延或前移。比如 A、B、C、D 把 D 移到 0，结果是 D、A、B、C。
  - 返回 200 和更新后的待办项。
- `DELETE /v1/lists/{list_id}/items/{item_id}` 返回 204，后面的项位置依次前移。
- 待办项必须属于路径里的清单，否则 404。
- 增、改、删待办项需要 owner 或 edit 身份。

### 4. 分享

- `POST /v1/lists/{list_id}/shares`，请求 `{"email": "b@example.com", "permission": "read"}`，`permission` 只能是 `read` 或 `edit`，否则 400。只有 owner 能分享，edit 和 read 返回 403。
  - 邮箱不区分大小写；对应的用户不存在返回 404；分享给自己返回 400。
  - 第一次分享给这个人返回 201；已经分享过，就把权限改成这次的，返回 200。同一个清单对同一个人永远只有一条分享。
  - 响应：`{"user_id": "...", "email": "b@example.com", "permission": "read"}`。
- `GET /v1/lists/{list_id}/shares`，只有 owner 能看，返回 200：`{"shares": [{"user_id": "...", "email": "...", "permission": "read"}, ...]}`，按分享先后排。edit 和 read 返回 403。
- `DELETE /v1/lists/{list_id}/shares/{user_id}`：
  - owner 取消对某人的分享，返回 204；
  - 被分享的人删自己 = 退出这个清单，返回 204；
  - edit 或 read 删别人的分享返回 403；
  - 这个人本来就没被分享，返回 404。

### 5. 复制

- `POST /v1/lists/{list_id}/copy`，请求 `{"title": "我的周末采购"}`，`title` 可以不填（不填就沿用原标题），填了规则同新建。我只要看得到原清单（owner、edit、read 都行）就能复制。
- 复制出来的是一个全新的清单：我是 owner；待办项的文字和顺序和原清单一样，`done` 一律重置为 false；原清单的分享不带过去。
- 复制品和原清单从此互不影响：改、删其中一边的标题或待办项，另一边不变；原清单被删除，复制品照样在。
- 返回 201 和新清单的清单摘要（`permission` 为 `owner`）。

## 交付要求

- wrangler 配置文件里 D1 的绑定名叫 `DB`；数据库迁移放在 `migrations/` 目录，用 `npx wrangler d1 migrations apply DB --local` 能建好表。
- 本地用 `npx wrangler dev --local` 能启动。密钥从环境变量读（本地放在 `.dev.vars`），不要写死在代码里。
- 多个请求可能同时到达（比如几个人同时往同一个清单里加项、删项，同一个邮箱同时注册，同时把清单分享给同一个人），结果必须和一个一个来时一样正确：待办项位置保持连续不重复，分享不出现重复记录。
- 自己写测试验证上面的规则。
- 不要部署，不要登录 Cloudflare 账号。
