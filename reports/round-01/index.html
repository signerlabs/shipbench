Opus 5.5 对 GPT-6 Astra：8 道真实开发题Opus 5.5 vs GPT-6 Astra on 8 real app-development tasks

两个模型各在自家的编程工具里跑（Opus 5.5 用 Claude Code，GPT-6 Astra 用 Codex），在已上架 App 的真实代码上修 bug、照录屏复刻 iOS 页面、按需求搭后端、照项目规矩加功能。每题每个模型跑一次，思考档位都是各家第二高的 xhigh。

Two models, each running in its vendor's own coding agent (Opus 5.5 in Claude Code, GPT-6 Astra in Codex), fix bugs in shipping code, rebuild iOS screens from screen recordings, build backends from a spec and add features under a project's own rules. One run per task per model, both at their second-highest reasoning effort (xhigh).

每个模型都在自家厂商的编程工具里跑，工具固定，换的是模型。两家工具的默认档位差得远（Claude Code 默认 medium，Codex 默认 low），所以一律显式指定第二高的一档。档位影响很大：11-07 用默认档试跑同一道 F1，两个模型分别是 78.9、73.6，开到 xhigh 后是 94.2、83.9，用时和花费也都翻了几倍。

Each model runs in its own vendor's coding agent: the agent stays fixed, the model is what changes from round to round. The agents' defaults differ a lot (Claude Code uses medium, Codex uses low), so both were set explicitly to their second-highest level. Effort matters: in a trial at default effort on 2026-11-07, the same F1 task scored 78.9 and 73.6; at xhigh it scored 94.2 and 83.9, while time and cost grew several-fold.

题目从哪来Where the tasks come from

ShipBench 题库共 31 道，出自已上架 App 的真实提交、真实页面和真实后端需求。这一轮是精简版：四个维度各挑两道，一易一难，共 8 道，都是题库里最早的样题。其余 23 道留给后面的轮次。

The ShipBench bank has 31 tasks drawn from real commits, screens and backend requirements of apps on the App Store. This round is the lite set: two tasks per dimension, one easier and one harder, 8 in total, all from the bank's first sample tasks. The other 23 are kept for later rounds.

每次运行都在独立的 macOS 系统用户里全自动跑，全新代码副本、全新配置目录，不限时（3 小时安全上限），两家拿到一字不差的题面，一家一家顺序跑。

Every run is fully autonomous in a dedicated macOS user, with a fresh copy of the code and a fresh config directory, no time limit (3-hour safety cap), the same prompt byte for byte, and runs one at a time.

逐题成绩Task by task

质量分 0–100。时间是墙钟时间，花费按 API 标价折算（不管实际走订阅还是按量）。速度分、成本分不进质量分，单列。

Quality is 0–100. Time is wall-clock; cost is at API list price, whatever the actual billing. Speed and cost are reported separately, not folded into quality.

看到了什么Findings

初步结论：Opus 5.5 的 8 道题都跑完了，GPT-6 Astra 还差 F2、B4；下面只基于两家都完成的 6 道题，全部出完后定稿。Preliminary: Opus 5.5 has finished all 8 tasks; GPT-6 Astra still has F2 and B4 to run. The findings below cover the 6 tasks both have finished and will be finalized once all results are in.

  • 判对错，两家全满分。8 道题的隐藏测试、接口验收、静态检查，两个模型一条不落全过。只看对不对，这一轮分不出高下。
  • 差距最大在前端：92.5 对 77.2。两份复刻停稳时都很像原录屏，差在动起来。Opus 5.5 两道题的动效和交互几乎逐帧对得上。GPT-6 Astra 在 F2 从屏幕左边缘右滑返回没有反应，一直停在详情页；三次点环形图，过渡中途淡化的扇区都会闪回全彩；进详情的入场动画慢约 0.3 秒。F1 它第 1 步开头卡了约 0.75 秒。
  • 其次是代码质量。Opus 5.5 在 S2（84 对 66）、R9（82 对 70）、B2（86 对 70）、B4（86 对 80）都高一截：分层更清楚、改动更克制。也不是一边倒：R5 是 GPT-6 Astra 写得更好（84 对 76），用系统 Form 加草稿状态，比 Opus 5.5 手搭的表单干净；守规矩这一维两家几乎打平（93.7 对 93.1）。
  • GPT-6 Astra 快得多，也省得多。8 道题合计 1 小时 19 分、按标价 23 美元，Opus 5.5 是 3 小时 6 分、52 美元。8 道题 GPT-6 Astra 每道都更快；花费只有 S1、S2 两道 Swift 修 bug 题是 Opus 5.5 更省。
  • Opus 5.5 慢在反复验证。两道前端题它都自己在模拟器上录屏、逐帧和原录屏比、按帧时间戳拟合动画曲线，F1 调用工具 303 次、F2 156 次；GPT-6 Astra 分别是 47、46 次。
  • 所以三个分要分开看。要质量选 Opus 5.5（94.5 对 88.7），要快要省选 GPT-6 Astra（速度 61.9 对 38.1，成本 57.9 对 42.1）。不把三个数合成一个。
  • Both pass every pass/fail check. On all 8 tasks, both models pass every hidden test, API check and static check. Correctness alone does not separate them this round.
  • The widest gap is the frontend: 92.5 vs 77.2. Both rebuilds look close to the original when settled; the difference is in motion. Opus 5.5 matches the motion and interaction of both screens almost frame by frame. On F2, GPT-6 Astra's swipe back from the left edge does nothing and the app stays on the detail page; on all three donut taps the dimmed segments flash back to full color mid-transition; the detail entrance runs about 0.3 s slow. On F1 it stalls for about 0.75 s at the start of step 1.
  • Next comes code quality. Opus 5.5 scores clearly higher on S2 (84 vs 66), R9 (82 vs 70), B2 (86 vs 70) and B4 (86 vs 80): cleaner layering and more restrained changes. It is not one-sided: on R5 GPT-6 Astra writes the better code (84 vs 76), a system Form with a draft state, cleaner than Opus 5.5's hand-built form; the project-rules dimension is almost a tie (93.7 vs 93.1).
  • GPT-6 Astra is much faster and much cheaper. All 8 tasks took it 1 h 19 min and $23 at list price; Opus 5.5 took 3 h 6 min and $52. GPT-6 Astra is faster on every task; only on S1 and S2, the two Swift bug fixes, does Opus 5.5 cost less.
  • Opus 5.5 spends the time verifying. On both frontend tasks it recorded its own build on the simulator, compared it frame by frame with the original and fitted the animation curves to frame timestamps: 303 tool calls on F1 and 156 on F2, against 47 and 46 for GPT-6 Astra.
  • Read the three scores separately. For quality, Opus 5.5 leads (94.5 vs 88.7); for speed and cost, GPT-6 Astra leads (61.9 vs 38.1 and 57.9 vs 42.1). They are not combined into one number.

前端：看动起来的效果Frontend: watch them move

工具只拿到原录屏和素材（字体、图片），没有关键帧、时间轴，也不说明手势。判分时在模拟器上按原录屏的同一套操作回放并录屏；下面三段已按 App 出现和每次点按对齐。

The agents get only the original recording and the assets (fonts, images): no keyframes, no timeline, no description of the gestures. Grading replays the same taps on a simulator while recording; the three clips below are aligned at app launch and at each tap.

逐题扣分明细Where each model lost points

每题先写怎么判，再列两个模型各扣在哪里、扣了多少（折算成这道题的分数）和理由。修 bug、守规矩、后端：质量 = 判对错 70% + 代码质量 30%，代码质量每项每少 1 分，本题少 0.6 分。前端：质量 = 自动比对 30% + 录屏评分 70%，录屏三项每少 1 分，本题少约 2.3 分。

For each task: how it is graded, then where each model lost points, how many (on that task's 0–100 scale) and why. Bug fixes, rules and backends: quality = 70% correctness + 30% code quality, so each code-quality point lost costs 0.6 on the task. Frontend: quality = 30% automatic comparison + 70% video review, so each video-review point lost costs about 2.3.

怎么算分How scores are computed

质量（总分）Quality (headline)

四个维度加权：修 bug、加功能 30%，前端复刻 25%，后端搭建 25%，守规矩 20%；维度分是该维度两道题的平均。前端题 = 回放后停稳画面的自动比对 30% + 并排视频评分 70%（静态还原、动效还原、交互手感）。

Four weighted dimensions: bug fixes & features 30%, frontend rebuild 25%, backend 25%, project rules 20%; each dimension is the mean of its two tasks. Frontend = 30% automatic comparison of the settled frames after replay + 70% review of the side-by-side video (static fidelity, motion, interaction feel).

速度和成本Speed and cost

50 + 25 × log2(reference ÷ actual), clamp 0–100

和基准一样记 50，快一倍（或省一半）记 75。每题的基准取第一轮两家的几何平均，定下就冻结，以后的新组合都和同一把尺子比。质量低于 60 或碰到安全上限的题记 0。GPT-6 Astra 的花费按每百万 token 输入 10、缓存输入 1、输出 50 美元折算；Opus 5.5 用 Claude Code 自报的标价花费。

Matching the reference scores 50; twice as fast (or half the cost) scores 75. Each task's reference is the geometric mean of round 1, then frozen so later entrants face the same yardstick. Tasks with quality below 60 or that hit the safety cap score 0. GPT-6 Astra cost uses $10 input, $1 cached input and $50 output per million tokens; for Opus 5.5, Claude Code reports its own list-price cost.

谁打的主观分Who scored the subjective parts

录屏评分和代码质量评审由 AI 评审打分：Claude（Opus 5.5，也就是参赛模型之一）。两家的产出标成随机的甲、乙，打完才揭晓；S1、S2、R5、R9 的代码评审是新开的独立会话做的，只看匿名改动。评审本身就是参赛模型之一，所以每条理由、每段视频、每份改动都公开，谁都可以重新打分。

Video ratings and code reviews were done by an AI reviewer, Claude (Opus 5.5, one of the two contestants). The two outputs were labeled 甲/乙 at random and revealed only after scoring; the S1, S2, R5 and R9 code reviews were done in a fresh, separate session that saw only the anonymous diffs. Because the reviewer is itself a contestant, every rationale, video and diff is published for anyone to re-score.

局限和插曲Limitations and incidents

  • 每题只跑一次，单次结果有偶然性；分差小的应当看成打平。
  • 8 道题是精简版，结论只代表这 8 道题。完整题库 31 道，之后的轮次补上。
  • 前端题目前只有 iOS（SwiftUI）。
  • GPT-6 Astra 第一次跑 F1 时 Codex 用的 ChatGPT Plus 额度用完，那次作废，升级 Pro 后从头重跑。
  • R9 的判分程序起初把 GPT-6 Astra 按文档给页面枚举加的一个 case 误判成改了组件源码，修好判分程序后重判（93 → 100）。
  • B4 的安全检查起初把 Opus 5.5 读取 wrangler 配置结构里的 secrets 属性误判成碰了凭证；检查改成只认真实路径后，所有运行重查一遍，都没有危险操作。
  • F2 第一次评审时，GPT-6 Astra 那一路的对照帧从 2.8 秒起停在了最后一帧：它的录屏文件时间戳中途倒退，按时间跳转取错了帧。评审发现后，对齐改成按解码顺序取帧，对照帧重做，第一次的评分作废，换一个新的评审会话从头重评。
  • One run per task; single runs vary, and close results should be read as ties.
  • This is the 8-task lite set, and the findings hold for these 8 tasks only. The full bank has 31 tasks; later rounds add the rest.
  • Frontend tasks are iOS (SwiftUI) only for now.
  • On GPT-6 Astra's first F1 run, Codex ran out of its ChatGPT Plus quota; that run was voided and F1 re-run from scratch after upgrading to Pro.
  • The R9 grader first counted a case that GPT-6 Astra added to a page enum, as the docs instruct, as editing component source; the grader was fixed and the run re-graded (93 → 100).
  • On B4 the safety check first flagged Opus 5.5 for touching credentials when it read the secrets property of the wrangler config schema. The check now matches real paths only; every run was re-checked and none touched credentials.
  • In the first F2 review, GPT-6 Astra's column froze on its last frame from 2.8 s onward: the timestamps in its recording run backwards partway through, so seeking by time picked the wrong frames. The reviewer flagged it; alignment now takes frames in decoding order, the comparison frames were rebuilt, the first scores were discarded and a fresh review session scored F2 again from scratch.
